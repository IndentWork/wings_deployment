# App Service Rollout Plan

Plan for getting Django running on Azure App Service with the Postgres backend.
This doc exists so we can resume mid-task across sessions.

## The 4 phases

### Phase 1 — Web App Terraform module
Create `modules/web-app/` that:
- Creates `azurerm_linux_web_app` running the container image from ACR
- Sets up VNet integration so the app can reach private Postgres
- Uses system-assigned managed identity
- Generates Django `SECRET_KEY`, stores in Key Vault
- Sets app settings (env vars) the app needs at boot

### Phase 2 — Wire dependencies in dev environment
- ACR pull: grant the web app's managed identity `AcrPull` role
- Key Vault: grant the managed identity `Get/List` on secrets
- Postgres: pass FQDN + credentials so the app builds `DATABASE_URL`
- Network: pass `app_subnet_id` for VNet integration

### Phase 3 — Image version control
- `image_version` variable per environment
- Manual promotion model: change the version in tfvars / variables.tf default → PR → merge → deploy
- Default to `latest` for dev only; pin specific versions for qa/prod when enabled

### Phase 4 — Deployment slot (blue-green swap)
- Add a `staging` slot alongside production
- Deploys go to staging first, then swap
- Verify health before swap, instant rollback by swap-back
- Out of scope for branch 1 — separate PR

## What still might break — open items

1. **Container start health check** — App Service may probe `/` before Django is ready. May need to add a `WEBSITES_HEALTHCHECK_MAXPINGFAILURES` or similar.
2. **First-boot migrations** — `python manage.py migrate` is not run anywhere yet. The DB exists but has no Django tables. Need a startup hook or manual run.
3. **Static files** — `collectstatic` runs at Docker build time but Whitenoise (or similar) is needed to serve them. Currently `STATIC_ROOT` is set but no serving middleware.
4. **HTTPS-only / TLS settings** — App Service serves HTTPS by default but Django settings should set `SECURE_PROXY_SSL_HEADER`.
