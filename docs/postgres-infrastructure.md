# Postgres Infrastructure Plan

## Overview

Each environment (dev, sb) gets a private Azure Postgres Flexible Server connected to the App Service
via VNet. No public access — the database is only reachable from within the VNet.

## Resources per environment

```
Resource Group
├── VNet (modules/network)
│   ├── Subnet: postgres  — delegated to Microsoft.DBforPostgreSQL/flexibleServers
│   ├── Subnet: app       — for App Service VNet integration
│   ├── Private DNS Zone: privatelink.postgres.database.azure.com
│   └── DNS Zone VNet Link
│
├── Key Vault (modules/key-vault)
│   ├── Secret: postgres-admin-password
│   └── Access policy: App Service managed identity (read secrets)
│
└── Postgres Flexible Server (modules/postgres-flexible)
    ├── Version: 14
    ├── SKU: B_Standard_B1ms (1 vCore, 2GB RAM — cheapest burstable)
    ├── Storage: 32GB
    ├── Admin password: generated by random_password, stored in Key Vault
    ├── Delegated subnet: from network module
    └── Private DNS zone: from network module
```

## Module build order

1. `modules/network` — no dependencies
2. `modules/key-vault` — no dependencies
3. `modules/postgres-flexible` — depends on network (subnet_id, dns_zone_id) and key-vault (vault_id)

## Modules to create

### modules/network

**Inputs:**
| Variable | Description | Example |
|---|---|---|
| `project` | Project name | `wings` |
| `env` | Environment | `dev` |
| `location` | Azure region | `southindia` |
| `resource_group_name` | RG to deploy into | from resource-group module |
| `vnet_address_space` | VNet CIDR | `["10.0.0.0/16"]` |
| `postgres_subnet_cidr` | Subnet for Postgres | `10.0.1.0/24` |
| `app_subnet_cidr` | Subnet for App Service VNet integration | `10.0.2.0/24` |

**Outputs:**
| Output | Description |
|---|---|
| `postgres_subnet_id` | Passed to postgres module |
| `app_subnet_id` | Passed to app service module |
| `private_dns_zone_id` | Passed to postgres module |
| `vnet_id` | VNet resource ID |

## Naming convention

| Resource | Pattern | Example (dev) |
|---|---|---|
| VNet | `vnet-{project}-{env}` | `vnet-wings-dev` |
| Postgres subnet | `snet-postgres-{project}-{env}` | `snet-postgres-wings-dev` |
| App subnet | `snet-app-{project}-{env}` | `snet-app-wings-dev` |
| Key Vault | `kv-{project}-{env}` | `kv-wings-dev` |
| Postgres server | `psql-{project}-{env}` | `psql-wings-dev` |
| KV secret (pg password) | `postgres-admin-password` | — |

**Note:** Key Vault names must be globally unique, 3–24 chars, alphanumeric + hyphens only.

## Address space

| Environment | VNet | Postgres subnet | App subnet |
|---|---|---|---|
| dev | `10.0.0.0/16` | `10.0.1.0/24` | `10.0.2.0/24` |
| sb | `10.1.0.0/16` | `10.1.1.0/24` | `10.1.2.0/24` |

## App Service connection (future)

Once the App Service module is built:
- App Service gets VNet integration using `app_subnet_id` from network module
- `DATABASE_URL` env var set to Postgres FQDN from postgres module
- Password read from Key Vault via Key Vault reference in App Service app settings
- `DJANGO_SETTINGS_MODULE=wings.settings_azure` env var tells Django to use Postgres
